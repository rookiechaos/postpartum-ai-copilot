**需要优先修复的代码问题**

1. **[P1] 启用 2FA 后仍直接签发有效令牌。** [auth_routes.py](../backend/api/auth_routes.py#L130) 在密码正确后创建 access/refresh token；后面的 2FA 分支只有 `pass`。`requires_2fa` 标志不参与 JWT 校验，因此知道密码即可直接调用受保护接口。独立执行实际登录函数体、替换外部服务后，已复现“2FA 已启用、验证调用次数为零、仍返回两种令牌”。应先签发仅可完成验证的短期 challenge，通过 TOTP 或备用码后再签发正常令牌，同时覆盖 refresh 和失败时的处理。

2. **[P1] Service Worker 的 API 缓存可能跨账号返回私人数据。** [sw.js](../frontend/public/sw.js#L65) 把所有 GET API 请求交给网络优先策略；[写入与回退](../frontend/public/sw.js#L90) 共用 runtime cache。[logout](../frontend/src/utils/api.js#L233) 仅清理本地认证状态。账号 A 的同一 URL 响应可能在账号 B 离线请求时命中缓存，影响个人资料、记录和导出内容。使用实际 SW 代码和隔离的网络/Cache 模拟已复现。缓存匹配不能默认用不同 Authorization 值隔离用户，需要相应的响应 Vary 或显式的用户分区。[Cache 匹配规则](https://developer.mozilla.org/en-US/docs/Web/API/Cache/match)。建议禁止缓存认证/API 响应，并在新 SW 激活时清理旧的私人响应缓存。

3. **[P1] 默认日志配置会阻止后端导入。** [logging_service.py](../core/services/logging_service.py#L18) 默认使用项目外层的相对日志目录，但 [validate_file_path](../core/services/code_security_audit.py#L34) 拒绝任何包含父目录跳转的路径。错误是 `ValueError`，不会被仅捕获 `ImportError` 的分支处理。独立执行该校验已确认默认值被拒绝。应以项目根目录解析允许的日志目录，再做目录边界校验和父目录创建。

4. **[P1] Docker worker 缺少必需的 JWT 配置。** [docker-compose.yml](../docker-compose.yml#L61) 为 API 传入 `JWT_SECRET_KEY`，却没有给 worker 传入该值，也未挂载本地环境配置。[get_settings](../backend/config/settings.py#L157) 默认按生产配置检查该密钥并拒绝默认值。修复其他启动阻塞后，worker 仍会因配置缺失退出。应共享必要配置并验证 API、worker 均能独立启动。

5. **[P2] 自定义数据库异常会将内部错误原样返回客户端。** [error_handler.py](../backend/middleware/error_handler.py#L51) 不区分生产模式，直接返回 `exc.message` 和 `exc.details`；[数据导出路由](../backend/api/data_export_routes.py#L50) 等处把底层异常写入这些字段。数据库地址、SQL 参数或用户数据可能随错误暴露。独立执行真实异常处理函数已复现内部标记进入响应。应对客户端返回稳定的安全错误信息，内部详情仅进入经过脱敏的日志；验证错误也应移除原始 input 和不可序列化的异常上下文。
